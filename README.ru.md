# DeepCoolGo

**Мониторинг процессора на LCD-экране кулера DeepCool с настраиваемыми темами на Go.**

[![Лицензия: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Go](https://img.shields.io/badge/Go-1.26.6%2B-00ADD8?logo=go&logoColor=white)](go.mod)
[![Платформа: Linux](https://img.shields.io/badge/Platform-Linux-333?logo=linux&logoColor=white)](#требования)

[English](README.md) · Русский

</div>

DeepCoolGo получает загрузку, температуру, частоту и энергопотребление процессора
из системных интерфейсов Linux и выводит их на LCD-экран совместимого кулера
DeepCool с разрешением 320 × 240 пикселей. Приложение взаимодействует с экраном
через `libusb`, а оформление загружает из Go-плагина (`.so`).

## Возможности

- Отображение загрузки (%), температуры (°C), частоты (ГГц) и энергопотребления (Вт) процессора.
- Пять готовых тем и шаблон для создания собственного оформления.
- Программная отрисовка текста, фигур и шкал с поддержкой альфа-смешивания.
- Настраиваемый интервал сбора метрик; кадр отправляется только при изменении данных.
- Прямое взаимодействие с устройством по USB и установка в качестве службы systemd.

## Требования

| Компонент | Требование |
|---|---|
| Операционная система | Linux; для установки службы требуется systemd. |
| Экран | LCD-экран DeepCool с разрешением 320 × 240 и USB ID `3633:0026`. |
| Go | **1.26.6 или новее**, согласно [go.mod](go.mod). |
| Инструменты сборки | Git, Make, компилятор C и `pkg-config`. Makefile включает CGO. |
| Библиотека | `libusb-1.0` и заголовочные файлы для разработки, необходимые пакету `gousb`. |
| Права доступа | Доступ к USB-устройству и чтению перечисленных ниже источников метрик. В примерах запуска используется `sudo`. |

Сейчас приложение распознаёт только устройства с USB ID `3633:0026` и совместимым
интерфейсом. Если подключено несколько совместимых экранов, приложение использует
первый, который удалось открыть, в порядке номера USB-шины и адреса устройства.

Все перечисленные источники метрик должны быть доступны для чтения:

| Метрика | Источник |
|---|---|
| Загрузка процессора | `/proc/stat` |
| Температура | `hwmon`: `k10temp` с меткой `Tctl` или `coretemp` с меткой `Package id 0` |
| Частота | `/sys/devices/system/cpu/cpu[0-9]*/cpufreq/scaling_cur_freq` |
| Энергопотребление | `/sys/class/powercap/intel-rapl:0/energy_uj` |

Если получить хотя бы одну метрику не удалось, приложение записывает
предупреждение в журнал и пропускает обновление всего экрана. Обход отсутствующего
счётчика энергии или датчика температуры пока не реализован.

Установите зависимости для своего дистрибутива:

```sh
# Fedora / Nobara
sudo dnf install git make golang gcc pkgconf-pkg-config libusbx-devel

# Debian / Ubuntu
sudo apt update
sudo apt install git make golang gcc pkg-config libusb-1.0-0-dev

# Arch Linux
sudo pacman -S --needed git make go gcc pkgconf libusb
```

Сверьте вывод `go version` с [go.mod](go.mod): версия Go в репозитории вашего
дистрибутива может быть ниже требуемой.

## Быстрый старт

```sh
git clone https://github.com/AlexanderBazarov/DeepCoolGo.git
cd DeepCoolGo

# Собрать приложение и плагины, установить темы для текущего пользователя
# и создать конфигурацию, если её ещё нет.
make dev

# Сохранить путь к пользовательской конфигурации при запуске через sudo.
sudo env XDG_CONFIG_HOME="${XDG_CONFIG_HOME:-$HOME/.config}" ./build/deepcoolgo
```

`make dev` копирует плагины в `$XDG_CONFIG_HOME/DCGO/Themes`, а если
`XDG_CONFIG_HOME` не задан — в `~/.config/DCGO/Themes`. Новая конфигурация
использует тему `aether.so` и интервал сбора метрик **5 секунд**. Существующий
файл конфигурации сохраняется; проверьте `themes_path`, если в нём указан
другой каталог.

Явное указание `XDG_CONFIG_HOME` в команде запуска позволяет использовать вашу
конфигурацию, даже если `sudo` меняет окружение пользователя. Первое обновление
экрана происходит через один интервал сбора метрик. Для остановки нажмите `Ctrl+C`.

Чтобы только собрать проект, без копирования плагинов и создания конфигурации,
выполните `make`. Настройка автоматического запуска описана в разделе
[«Запуск как служба»](#запуск-как-служба-systemd).

## Конфигурация

Приложение загружает конфигурацию один раз, при запуске:

| Условия запуска | Файл конфигурации |
|---|---|
| Текущий пользователь, `XDG_CONFIG_HOME` не задан | `~/.config/DCGO/config.yml` |
| Задан `XDG_CONFIG_HOME` | `$XDG_CONFIG_HOME/DCGO/config.yml` |
| Установленная служба systemd | `/etc/deepcoolgo/DCGO/config.yml` |

Если файла нет, приложение создаёт его со значениями по умолчанию. Плагины тем
при этом не собираются и не устанавливаются.

Пример конфигурации службы, установленной через `make install`:

```yaml
# Интервал сбора метрик в секундах; допустимы дробные значения, например 0.5.
refresh_rate: 30

# Имя файла плагина в каталоге themes_path.
theme: aether.so

# Абсолютный путь к каталогу с собранными плагинами.
themes_path: /usr/local/lib/deepcoolgo/themes
```

| Параметр | Значение по умолчанию в приложении | Описание |
|---|---|---|
| `refresh_rate` | `30` | Интервал сбора метрик в секундах; должен быть больше нуля. |
| `theme` | `aether.so` | Имя файла плагина относительно `themes_path`. |
| `themes_path` | `$HOME/.config/DCGO/Themes` | Каталог плагинов; по умолчанию определяется через домашний каталог пользователя, запустившего процесс. |

Указывайте абсолютный путь в `themes_path`: `~` и переменные окружения в значениях
YAML не раскрываются. Каталог плагинов по умолчанию не зависит от
`XDG_CONFIG_HOME`, однако `make dev` явно записывает соответствующий путь при
создании конфигурации.

`make dev` задаёт интервал 5 секунд в новом файле конфигурации; `make install`
и само приложение по умолчанию используют 30 секунд. После изменения любого
параметра перезапустите приложение или службу.

## Темы

Превью получены из реального кода тем в разрешении экрана — 320 × 240 пикселей.
Во всех примерах используются одинаковые демонстрационные показания:
**загрузка 42%, мощность 65 Вт, температура 56 °C и частота 4,2 ГГц**.

Aether — тема по умолчанию. LM360 и QuietBeat показывают мощность, температуру
и частоту, без загрузки CPU. Пределы шкал Stats задаются в
[plugins/stats/main.go](plugins/stats/main.go). `custom.so` — заготовка
для собственного оформления.

Команда `make plugins` собирает все шесть плагинов в `build/themes/`.
Чтобы сменить тему, укажите имя файла плагина в параметре `theme` файла
`config.yml` и перезапустите приложение. Плагины загружаются при запуске;
автоматическая перезагрузка не реализована.

Приложение и плагины должны быть собраны одной версией Go, с совместимыми
настройками сборки и одинаковыми версиями общих пакетов и зависимостей. После
изменения общего кода или версии Go пересоберите весь проект командой
`make clean && make`. Затем повторно выполните `make dev` или `sudo make install`,
чтобы обновить установленные копии.

Интерфейс плагина, примитивы отрисовки и примеры проверки без кулера описаны
в [руководстве по созданию тем](themes/CREATING_THEMES.ru.md).

## Запуск как служба (systemd)

Из корня проекта установите приложение и включите автоматический запуск:

```sh
make
sudo make install
sudo make enable

systemctl status deepcoolgo
journalctl -u deepcoolgo -f
```

`make install` устанавливает приложение, плагины, службу systemd и начальную
конфигурацию. `make enable` перечитывает конфигурацию systemd, запускает службу
и включает её запуск при загрузке системы. Поставляемая служба работает от root
и перезапускает процесс при аварийном завершении.

| Путь по умолчанию | Содержимое |
|---|---|
| `/usr/local/bin/deepcoolgo` | Исполняемый файл приложения |
| `/usr/local/lib/deepcoolgo/themes/*.so` | Плагины тем |
| `/usr/lib/systemd/system/deepcoolgo.service` | Файл службы systemd |
| `/etc/deepcoolgo/DCGO/config.yml` | Конфигурация службы, сохраняется при переустановке |

`PREFIX` по умолчанию равен `/usr/local`. Makefile также поддерживает `DESTDIR`
для установки в промежуточный каталог и отдельное переопределение путей;
подробнее — в [Makefile](Makefile).

После изменения конфигурации службы или переустановки приложения выполните:

```sh
sudo systemctl restart deepcoolgo
```

Чтобы остановить службу и отключить автозапуск, выполните `sudo make disable`.
Чтобы удалить установленное приложение, сохранив конфигурацию, выполните
`sudo make uninstall`. Используйте те же переопределения путей, что и при установке.

### Права на USB

В примерах запуска и поставляемой службе приложение работает от root для доступа
к USB-устройству и источникам метрик. Для запуска от обычного пользователя
настройте права на USB-устройство, например через `udev`, и убедитесь, что этот же
пользователь может читать источники метрик, включая счётчик энергии RAPL.
Одних прав на USB может быть недостаточно.

## Как это устроено

1. [monitor/](monitor/) собирает метрики из системных интерфейсов Linux в структуру `themes.CPUData`.
2. Функция `Screen` выбранного плагина преобразует эти данные в объекты отрисовки.
3. [deep_cool/](deep_cool/) объединяет объекты в кадр 320 × 240 в формате RGB565.
4. [system/](system/) передаёт заголовок кадра и данные пикселей по USB через `gousb`.

[app/runner.go](app/runner.go) повторяет этот цикл каждые `refresh_rate` секунд.
Если значения метрик совпадают с последними успешно выведенными данными,
отрисовка и передача кадра пропускаются.

## Разработка

Выполняйте команды из корня проекта:

```sh
make            # Собрать приложение и все плагины
make build      # Собрать только build/deepcoolgo
make plugins    # Собрать только build/themes/*.so
make dev        # Собрать проект и установить темы для текущего пользователя
make test       # Выполнить go test ./...
go vet ./...    # Выполнить статический анализ
make clean      # Удалить результаты сборки
```

В [руководстве по созданию тем](themes/CREATING_THEMES.ru.md) есть пример
предварительного просмотра в PNG. Создайте по этому примеру файл
`cmd/preview/main.go` и выберите существующую тему, например
`themes.AetherTheme{}`, вместо описанной в руководстве `NebulaTheme`.
Затем выполните `go run ./cmd/preview`. Так можно проверить расположение
элементов без подключённого кулера; для сборки по-прежнему нужны указанные выше
зависимости.

| Путь | Назначение |
|---|---|
| [main.go](main.go) | Запуск, настройка зависимостей и обработка сигналов |
| [app/](app/) | Цикл сбора метрик и обновления экрана |
| [config/](config/) | Загрузка, проверка и значения конфигурации по умолчанию |
| [monitor/](monitor/) | Сбор метрик процессора |
| [deep_cool/](deep_cool/) | Поиск экрана, примитивы отрисовки и формирование кадра |
| [system/](system/) | USB-соединение и передача данных |
| [themes/](themes/) | Интерфейс и реализации тем, ресурсы и документация |
| [plugins/](plugins/) | Точки входа, собираемые в плагины `.so` |
| [packaging/](packaging/) | Шаблоны службы и конфигурации, сборка пакетов через RPM и nFPM |
| [debian/](debian/) | Файлы для сборки Debian-пакета |

## Диагностика

| Симптом или сообщение в журнале | Что проверить |
|---|---|
| `compatible DeepCool displays not found` | Проверьте USB-подключение и идентификатор устройства. Сейчас распознаётся `3633:0026` с совместимым интерфейсом. |
| `open compatible DeepCool display` | Проверьте права на USB-устройство и не занято ли оно другим процессом. |
| `load config` | Прочитайте полное сообщение об ошибке; проверьте синтаксис YAML, права на файл и условие `refresh_rate > 0`. После успешной загрузки путь к конфигурации выводится в журнал. |
| `read theme plugin` | Проверьте `themes_path` и наличие файла плагина. Выполните `make dev` для локального запуска или переустановите плагины службы. |
| `plugin was built with a different version of package ...` | Выполните `make clean && make` с согласованными настройками сборки, переустановите приложение и плагины, затем перезапустите. |
| `collect metrics` / `read power` | Счётчик RAPL отсутствует или недоступен для чтения. Обновление всего экрана пропускается. |
| `read cpu temperature` / `read cpu frequency` | Проверьте датчик и источники `cpufreq`, перечисленные в разделе «Требования». Эти ошибки также препятствуют обновлению экрана. |
| Мощность равна `0` при первом измерении | Первое чтение счётчика энергии задаёт начальную точку для последующих расчётов мощности. |
| Экран не обновляется | Дождитесь одного интервала сбора метрик и проверьте журнал. При одинаковых значениях новый кадр не отправляется. |

## Участие в проекте

Сообщения об ошибках и pull request приветствуются. В описании проблемы укажите
дистрибутив, версию Go, USB ID устройства и соответствующие записи журнала.
При добавлении темы следуйте
[руководству по созданию тем](themes/CREATING_THEMES.ru.md).

Перед отправкой изменений кода отформатируйте Go-файлы и выполните
`go vet ./...`, `make test` и `make`.
